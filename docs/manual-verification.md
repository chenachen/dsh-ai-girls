# 手动验证

按 [README](../README.md#安装) 完成构建和 DSH 本地目录安装，再执行以下场景。自动化测试与手动结果分别记录；`npm run demo` 使用合成事件，不能替代真实会话验收。

## 准备

```sh
npm test
npm run test:host
npm run build
npm run doctor
```

macOS 额外运行 `npm run test:native` 检查透明像素命中。宿主模块路径可用 `DSH_APP_PATH` / `DSH_NODE_MODULES` 覆盖，规则见 README。

记录操作系统、架构、DSH 与 Cordis 版本、当前提交及构建时间。代码更新后，在当前任务结束时重启 DSH；同一入口卸载重装可能仍使用 ESM 缓存。

## 任务与桌面窗口

1. 创建 A、B 两个测试会话，让二者实际运行，再切换到第三个闲置会话。气泡应同时显示 A、B，标题和状态分别对应。
2. 最小化 DSH，观察气泡仍可见，并至少出现一次真实执行阶段或任务结束变化。
3. 恢复 DSH，再把浏览器或编辑器放在前面并持续输入文字。气泡应保持可见、继续更新且不夺走输入焦点。
4. 让 B 结束、A 继续运行。B 显示本轮结束，约 12 秒后结果卡消失；A 的工作状态与计时继续。
5. 触发审批和提问，确认等待气泡含具体事项；批准或回答后恢复执行状态。单次工具报错后继续执行不能显示整轮失败。
6. 分别触发正常结束、手动停止和最终失败，确认三种结果与对应文案分开。
7. 点击非当前会话的任务标题，确认 DSH 恢复并打开正确会话，没有发送消息或启动新执行。
8. 运行或等待期间重新加载插件，应恢复当前任务；闲置历史会话不弹出完成提示。

## 角色与设置

- 在设置页和桌面菜单分别切换十种形态、缩放与气泡显示，确认两端同步且重启后保留。
- 检查固定、顺序、收藏和随机轮换；随机不连续重复，收藏轮换只使用收藏列表。
- 输入轮换间隔后按回车或移开焦点保存；1–3600 秒内的整数生效，非法值不写入。
- 持续执行任务至少 10 分钟，期间切换角色、悬停和打开菜单，工作动画不冻结，也不插入角色闲聊。
- 所有任务结束并经过结果提示期后，进入闲置动画；闲置文案按低频策略出现。

## 命中、位置与生命周期

- 用真实鼠标点击角色透明空白处，确认下层应用收到点击；点击角色、名称和气泡时正常响应。直接向指定窗口投递的自动化点击不能证明跨应用穿透。
- 拖动到副屏后重启，再断开副屏，检查位置记忆与可见区域约束；覆盖不同显示器缩放比例。
- Windows 位置保存到 `%LOCALAPPDATA%\DshAiGirls\window.txt`；macOS 保存到 `~/Library/Application Support/DshAiGirls/window.json`。
- 隐藏或关闭 DSH 主窗口但保持宿主运行时，桌面角色继续工作；真正退出 DSH 后桌面进程退出。
- 在插件详情页停用、启用，确认窗口关闭后只恢复一个实例，偏好保留；卸载使用同一详情页的卸载按钮。
- 点击桌面窗口的「×」只关闭该窗口，DSH 任务继续；重新启用插件可恢复。

按[验收清单](acceptance.md)记录通过、失败或未覆盖及对应平台，不将 macOS 结果作为 Windows 的实机结论。
