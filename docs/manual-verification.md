# 桌面联调步骤

本文件供代码完成后手动验证。自动化测试不会控制桌面、发起模型请求或修改业务项目。

## 启动

在本仓库目录运行（Windows，Node.js 22 或以上）：

```powershell
npm ci
npm test
npm run test:host
npm run build
npm run doctor
npm run install:local
```

`test:host` 默认读取 `%USERPROFILE%\.dsh\profiles\node_modules` 中安装的 DSH 官方包。其他路径设置 `DSH_NODE_MODULES`。当前验证版本为 DSH `0.1.7-rc.2`、Cordis `4.0.4`。

本地安装默认修改 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.yml`，只添加带标记的开发入口，每次变更前自动备份。其他 profile 设置 `DSH_PROFILE_DIR`。准备好后，在没有需要保留的运行任务时重新启动 DSH 宿主或重新加载此插件；不要仅凭安装脚本成功就认为宿主已加载。

## 先看模拟窗口（可选）

`npm run demo` 会打开真实桌面窗口，用明确标注“合成事件”的样例运行约 65 秒，覆盖两个任务、工具执行、审批和结束。它不会调用模型。结束后子进程应自动退出。

## 核心场景

1. 在 DSH 创建 A、B 两个测试会话，让二者实际运行，再切换到第三个闲置会话。气泡同时显示 A、B 的执行信息，标题和状态分别对应。
2. 最小化 DSH。记录气泡仍然可见，并观察至少一次真实执行阶段或任务结束变化。
3. 恢复 DSH，再将浏览器或编辑器放在它前面。继续输入文字，确认气泡可见、状态更新且没有夺走输入焦点。
4. 让 B 结束，A 继续运行。B 显示“本轮结束 / 结果待查看”，A 的工作状态与计时继续；B 的结果卡约 12 秒后消失。
5. 触发审批与提问，确认显示“等待审批 / 等待输入”；回答或批准后恢复具体工具执行状态。工具报错但任务继续时不能显示整个任务失败。
6. 手动停止任务，再分别观察正常结束与最终失败。三种结果必须分开。
7. 在任务执行或待审批期间重新加载本插件，确认恢复现有任务和等待状态；闲置历史会话不突然弹出完成提示。
8. 停用本插件，确认其桌面程序退出。DSH 仍正常工作；重新启用后只能有一个本插件窗口。

## 气泡操作

- 拖动 AI 图标或气泡标题移动；位置保存在 `%LOCALAPPDATA%\DshAiGirls\window.txt`。
- 默认最多展示三个主任务，等待处理的任务优先；展开后查看其余任务和子任务。
- “−”收起气泡；右键 AI 图标恢复。没有任务且结果提示期结束时，气泡自动收起。
- “×”只关闭本插件窗口，不停止 DSH 中的任务。重新启用插件可恢复窗口。

## 移除本地开发入口

```powershell
npm run install:local -- --remove
```

移除只处理本脚本标记的配置块。随后重新加载插件配置或退出并重启宿主；移除配置不会主动终止当前 DSH 任务。
